# 文章、配圖與星曜擬人圖：Claude × GPT 合作流程提案（2026-10-28，Claude 初稿）

這份回應大正 10/28 09:37 的問題，以及 GPT 在 dazhen-booking #9 留言 6458355740 提的三個方向。大正排的順序是放在預約、付費、SEO 之後，所以**這裡只提方案和最小試行**，不改任何已上線的文章或圖。

## 0. 現況（從 repo 查得到的事實）

- 文章在 `content/blog/*.md`。寫作規範是 `docs/writing-guide.md`。
- 最近的文章多由 GPT（Codex）直接提交到 main（例如 27d10dc「Codex Publish approved…」），合併就上線，中間沒有自動檢查。
- 封面圖放在 `static/images/uploads/`，社群貼文圖放在 `static/images/social/`。原圖多半 2～3 MB，網站建置時會自動壓縮。
- `node scripts/check-articles.js --all` 的結果：5 篇封面沒有 `imageAlt`、1 篇沒有封面；2 篇沒有 tags、2 篇只有 1 個；多數文章沒有內部連結；`welcome` 這篇缺主題與正式網址代稱。
- **Claude 拿不到的**：
  - GPT 的「寫文章小幫手」設定與對話。
  - ChatGPT 產生圖片的歷史。
  - 大正手機裡的原始素材。
  - 能「看懂圖」的批次工具：Claude 一次看得了幾張圖，但不能保證抓到每個手指錯誤。

## 1. 建議的分工流程（一篇文章從題目到上線）

1. **找題目（GPT）**
   - GPT 找題目，來源可以是時事、節日、流年，或客人常問的問題。
   - 題目寫進 `docs/article-backlog.md`：一行一題，寫明主要問題、關鍵字、主題／小類、狀態。
   - Claude 可以補上兩件事：跟現有文章是否重複，以及可以互相連結的文章。
2. **寫稿與配圖（GPT）**
   - GPT 在**分支**寫稿，不直接推 main，開 PR，例如 `article/<slug>`。
   - 圖放 `static/images/uploads/<slug>/`，封面一定要有 `imageAlt`。
3. **自動檢查（GitHub，不用 AI）**
   - PR 一開，`scripts/check-articles.js` 就照寫作規範檢查。
   - 會檢查：欄位、slug、摘要長度、標題層級、一句一段、粗體數量、禁用說法（例如「財庫」）、內部連結、隱藏文字。
   - ✗ 會顯示紅叉，表示不能上線；△ 只是提醒。
4. **兩邊審稿**
   - Codex 自動審，看事實、寫作規範、命理說法有沒有違反大正的版本。
   - Claude 在大正說「看文章 PR #N」時審，重點是語氣、段落、SEO 標題與摘要、內部連結，並直接在 PR 改小地方。
   - 兩邊在 PR 留言討論，不在各自的對話裡各說各話。
5. **大正看預覽**
   - Netlify 每個 PR 會自動出預覽網址，手機就能看。
   - 大正說「上線」才合併。
   - 想排程發文，就把 `date` 設成未來的日期，再加一個每天自動重建網站的排程。這一項要大正同意才加。

這樣大正只需要做兩件事：說要寫什麼，看預覽後說上線。

## 2. 批量審圖（GPT 第 2 點）

**最小試行，這個 PR 已做：`scripts/image-report.js`。**

- 網站建置時會產生 `/admin/images/`。`/admin/` 已被 robots 排除，搜尋引擎找不到。
- 頁面列出所有文章用到的圖：縮圖、哪篇文章、封面或內文、替代文字、尺寸、大小。點縮圖可以放大。
- 自動標出這些狀況：
  - 找不到檔案
  - 沒有替代文字
  - 檔案太大
  - 封面比例不是橫式
  - 封面寬度不到 1200
  - 同一張圖用在多處
  - 上傳了但沒有文章用到
- 可以按問題種類篩選，也可以逐張勾「要改」並選原因。原因有：角色不對、比例或透視怪、手腳或手指錯、持物沒拿好、服飾紋樣錯、跟文章不搭、文字或錯字。
- 勾完按「複製清單」，貼給 GPT 或 Claude。勾選只存在那台裝置，不會改到任何檔案。
- 目前跑出來的結果：10 張封面裡，10 張檔案太大（原圖），5 張沒有替代文字，1 張比例不像封面，2 張重複使用。

**防漏、防錯、防覆蓋**

- 清單是程式從文章和資料夾掃出來的，不靠人記，所以不會漏圖。
- 每張都標「屬於哪篇文章」，配錯文章一眼看得出來。
- **不覆蓋原圖**：要改的圖用新檔名，例如 `-v2`，文章改指新檔。舊檔保留到大正確認，再一起清掉。
- **留給人判斷的**：圖畫得對不對、美不美、跟文章搭不搭。程式只負責讓人看得快、不漏看。

## 3. 星曜擬人圖的品質（GPT 第 3 點）

1. **角色規格表**：一顆星一張，放在 `docs/characters/<星名>.md`。內容包括：
   - 固定特徵：髮型、服色、持物、配飾、紋樣。
   - 可以變的地方：表情、姿勢、場景。
   - 不能出現的東西。
   - 1～2 張定稿參考圖。

   這份要大正確認過才算定稿。
2. **生成前檢核**（GPT 生圖前照著念一遍）：
   - 是哪一顆星。
   - 這張要表達文章的哪一句話。
   - 構圖：全身或半身，手裡拿什麼。
   - 避開難畫的姿勢，例如雙手交握、手指細節、手拿細長物品。
3. **每張結構複查**：照固定順序看——頭身比例、左右手腳數量、手和持物的接觸點、透視與地面、服飾紋樣是否和規格一致、畫面裡有沒有文字錯字。
   - 可以用上面的總覽頁，選原因標記。
4. **局部重繪與再審**：只重畫有問題的部分，存成新版本，再用同一份清單審一次。
5. **定稿與歷史**：定稿圖放進 repo。檔名帶版本號；不能直接取代舊圖，要先標舊圖淘汰、換掉引用，原檔保留到大正確認才刪。PR 裡寫明換了什麼、為什麼換。
6. **不要變成單一模板**：規格只固定「認得出是誰」的特徵。姿勢、場景、光線、構圖可以每篇不同。好看與否由大正看預覽決定。

**誰真正能做什麼**

- **GPT**（10/28 GPT 自己說明）：可以讀取、檢視圖片並做視覺與結構審查，可用的生圖工具能生成或修改圖片；能不能接觸指定素材、能不能自動批次處理，要看當下實際權限與工具，也不能保證抓到所有錯誤。目前**建立 PR、推送不在它被授權的工作範圍**（不代表技術上做不到），既有 PR 可以讀並在留言討論。
- **Codex（GitHub 上的自動審查）**：每次 `@codex review` 審 PR 的差異；實際能看哪些內容以它的工具為準，這裡不假設它看得到或看不到圖片。
- **Claude**：
  - 會：寫檢查與總覽工具、審稿與改稿、在 PR 上看少量圖片並指出明顯錯誤。
  - 不會：生成圖片，也沒辦法保證抓到每個手指錯誤。
- Claude 和 GPT 不能互相操控，只能透過 GitHub PR 留言接力。

## 4. 最小可試行步驟（建議順序）

1. 合併這個 PR：文章 PR 會自動檢查，網站多一頁配圖總覽。這兩樣都不會改到文章本身。
2. 下一篇新文章照第 1 節的流程走一次。GPT 目前沒被授權開 PR，所以先改成：GPT 把稿子與圖交給大正（或貼在 PR 留言），Claude 開分支與 PR、跑自動檢查，GPT 在 PR 留言審；等大正決定要不要讓 GPT 自己開 PR。
3. 先做一顆星的規格表試用，用大正最常用的星曜，例如天梁。
4. 舊文章的問題（沒有替代文字、tags、內部連結，welcome 這篇的分類）另開一個 PR 一次補，只補欄位、不改內文意思。
